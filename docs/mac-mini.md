# Mac mini как исполнитель локальных задач

Версия 1.2 добавляет запуск задач на mini. MacBook или iPhone отправляет команды через SSH; чтение музыки и запись отчётов происходят на mini. Для такого запуска не нужно монтировать внешний диск на MacBook через SMB.

## 1. Включить SSH на mini

На Catalina: **System Preferences → Sharing → Remote Login**. Разрешите доступ нужной локальной учётной записи в **Only these users**. Существующий доступ к экрану через Remote Management можно сохранить.

С MacBook проверьте порт, заменив обозначение адресом mini:

```sh
nc -vz -G 3 MINI_ZT_IP 22
```

`succeeded` подтверждает доступность порта, но ещё не успешную аутентификацию. Red Shield на MacBook в проверенной конфигурации остаётся включённым; маршруты ZeroTier используются для доступа к mini.

### Если Remote Login завис на «включается»

На самом mini проверьте службу:

```sh
sudo launchctl print system/com.openssh.sshd
```

В проверенном случае служба отсутствовала, и помогли команды **на mini**:

```sh
sudo launchctl enable system/com.openssh.sshd
sudo launchctl bootstrap system /System/Library/LaunchDaemons/ssh.plist
```

Это исправление конкретного случая, не обязательный шаг для работающего SSH. Если служба уже загружена или bootstrap вернул ошибку, сначала разберите её, затем повторно проверьте порт. Не отключайте существующий удалённый доступ к экрану.

## 2. Отдельный SSH-ключ

На MacBook создайте отдельный ключ, если такого файла ещё нет:

```sh
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_mini -C mini-access
```

Если появится вопрос о перезаписи существующего ключа, откажитесь и используйте другое имя. Парольную фразу выбирайте для своего сценария; при её использовании загрузите ключ в агент через `ssh-add ~/.ssh/id_ed25519_mini` перед автоматическим запуском.

До первого подключения сравните отпечаток сервера. На mini его можно получить так:

```sh
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

С MacBook подключитесь по паролю и подтвердите только совпадающий ключ:

```sh
ssh MINI_USER@MINI_ZT_IP
```

Выполните `exit`, чтобы вернуться на MacBook. Для установки ключа выполните там:

```sh
cat ~/.ssh/id_ed25519_mini.pub | ssh -o StrictHostKeyChecking=yes MINI_USER@MINI_ZT_IP '
set -e
umask 077
test ! -L "$HOME/.ssh"
test ! -L "$HOME/.ssh/authorized_keys"
mkdir -p "$HOME/.ssh"
chmod 700 "$HOME/.ssh"
touch "$HOME/.ssh/authorized_keys"
chmod 600 "$HOME/.ssh/authorized_keys"
IFS= read -r public_key
case "$public_key" in "ssh-ed25519 "*) ;; *) exit 1 ;; esac
if ! grep -Fqx -- "$public_key" "$HOME/.ssh/authorized_keys"; then
    printf "\n%s\n" "$public_key" >> "$HOME/.ssh/authorized_keys"
fi
'
```

Команда передаёт только открытый ключ и сохраняет существующие ключи на mini. Пароль пользователя mini вводится в локальном запросе SSH.

Добавьте блок из [ssh-config.example](../examples/ssh-config.example) в свой `~/.ssh/config`, подставив адрес и пользователя. Сохраните остальные настройки. Затем проверьте:

```sh
ssh -o BatchMode=yes mini-homelab whoami
```

## 3. Запуск задачи на mini

В проверенной установке Python 3.8.2 уже был доступен в `/usr/bin/python3`. Для чтения тегов отдельно установлен Intel `ffprobe` в каталог проекта. Сборки [Evermeet](https://evermeet.cx/ffmpeg/) рассчитаны на macOS 10.13 и новее; работоспособность выбранного бинарника проверена на Catalina. Совместимость актуального Homebrew с этой системой не предполагается.

Если старый curl на Catalina не может скачать файл по TLS, скачайте его через HTTPS на современном Mac и передайте через SSH. Не отключайте проверку TLS. Проверка SHA-256 до и после передачи подтверждает целостность передачи, но не заменяет проверку подписи издателя.

При переносе Python-скриптов учитывайте версию Python. В нашем инструменте заменены вызовы `str.removeprefix` и `Path.is_relative_to`, чтобы он работал на Python 3.8. Создан новый кэш: inode и device файлов при локальном доступе отличаются от значений через SMB. Выполненные планы копирования повторно не запускались.

**Зависимость публичной команды:** в домашнем каталоге mini должен существовать исполняемый `~/music-recovery`, принимающий аргументы `check` и `status`. Он запускает ваш установленный инструмент. Этот репозиторий не содержит персонального инструмента восстановления коллекции и не устанавливает его автоматически. Одного клонирования репозитория для анализа музыки недостаточно.

В проверенной приватной установке `check` читает музыку и создаёт новый отчёт, `status` показывает сохранённый результат. Копирование запускается отдельно после просмотра нового плана. Не запускайте копирование одновременно с двух компьютеров: их локальные блокировки не общие.

На MacBook из корня этого репозитория:

```sh
./scripts/mini-music
./scripts/mini-music status
```

По умолчанию используется SSH-алиас `mini-homelab`. Если ваш алиас другой:

```sh
MINI_SSH_HOST=my-mini ./scripts/mini-music status
```

Команда разрешает только `check` и `status`, использует известный ключ сервера и не запрашивает пароль. Она работает в текущем SSH-сеансе. В приватной установке удалённая команда использует `caffeinate -i` во время работы; это предотвращает обычный idle sleep, но не гарантирует продолжение после обрыва SSH или перезагрузки.

С iPhone можно подключиться к MacBook и вызвать ту же команду. Прямое подключение к mini использует его адрес и учётную запись; ключ MacBook сам по себе не настраивает доступ с iPhone.

## Что проверено и что остаётся

Проверены SSH по ключу и запуск на mini: 36 папок, 498 треков, 0 ошибок чтения тегов, 0 предложенных копий. Ссылки из списков сопоставлены в 26 из 31 папки. Музыка не изменена; спорные издания остаются на разбор. Проверка не охватывает всю коллекцию и не декодирует целиком каждый аудиофайл.

Фоновая очередь, общее меню, автоматическое резервное копирование, работа после сна/перезагрузки и отдельный тест мобильного доступа остаются следующими задачами. Архив кода и отчётов не является резервной копией музыки.
